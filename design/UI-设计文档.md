# PHPSerialize-labs 统一关卡页 UI 设计文档

> 状态:设计稿 + 静态原型,待评审。
> 原型入口:`design/prototype/index.html`(纯静态,无任何后端依赖)。

## 0. 设计前提(不可违反的约束)

1. **题目逻辑零改动**。靶场大量代码是刻意为之(EOL 版本行为、CVE 复现、eval 体系、
   裸输出风格),本方案只做"包装层",不碰任何 `LevelN/index.php` 的题目逻辑。
2. **保留两类关卡形态**:
   - **引导关(guided)**:知识点讲解 + 渐进提示,手把手;
   - **挑战关(challenge)**:提示很少、纯做题(如 Level 11 / 15 / 16 及练习题集),
     UI 上必须让"少提示"成为一种显式的、有仪式感的体验,而不是缺失。
3. **WriteUP 可达但防误触**:这是教学靶场,WP 必须一键可达;
   但默认折叠 + 二次确认,防止手滑剧透。

## 1. 页面结构(统一关卡页)

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏  [logo 探姬]  Level 7 / 18 · 实例化和反序列化   [← 上一关][目录][下一关 →] │
├──────────────────────────────────────────────────────────────┤
│ 标题区   关卡名  [引导模式] [难度★★] [考点tag: 反序列化基础]              │
│         一句话目标(从 HINT 提炼,不剧透)                              │
├──────────────────────────────────────────────────────────────┤
│ 知识卡(引导关才有;挑战关折叠为一句"本关不提供讲解")                    │
├──────────────────────────────────────────────────────────────┤
│ Tab 区  [ 题目源码 ] [ 作答 ] [ 提示 ] [ 解析 ]                       │
│  ├ 源码:代码高亮 + 行号;"关键代码"行整行高亮(引导关带旁注,挑战关不带)     │
│  ├ 作答:页内表单(自动带本关参数名) + curl 一行命令(一键复制)             │
│  │       + HackBar / 浏览器控制台 使用指引(新手第一次答题的入口)          │
│  ├ 提示:渐进式,点一条出一条(挑战关默认只有 1 条兜底提示)               │
│  └ 解析:剧透门(勾选"我已尝试") → 短解析 + EXP + 完整 WP 外链          │
├──────────────────────────────────────────────────────────────┤
│ 页脚  GitHub · hello-ctf.com · LICENSE                              │
└──────────────────────────────────────────────────────────────┘
```

设计取舍:
- **源码仍是主视图**(第一个 Tab):本项目"读代码学序列化"的特色保留;
  highlight_file 输出替换为前端高亮器(解决暗色模式不可读),源码文本不变。
- **作答独立成 Tab**:新手最痛的是"题目让我 POST,但我不知道怎么 POST"。
  表单 + curl + 工具指引三件套一次讲清;进阶玩家直接复制 curl。
- **提示渐进式**而非平铺:对应"引导→挑战"的梯度,提示条数本身承载难度曲线。

## 2. 数据驱动:关卡配置中心

新增 `config/levels.php`,一关一条配置;关卡页只读配置渲染,题目代码不感知 UI:

```php
7 => [
  'title' => '实例化和反序列化',
  'mode'  => 'guided',            // guided | challenge
  'diff'  => 1,                   // 1~3 → ★☆☆
  'tags'  => ['反序列化基础', '漏洞原理'],
  'goal'  => '通过 POST 参数 o 还原一个对象,让 backdoor() 读出 flag',
  'param' => ['method' => 'POST', 'name' => 'o'],
  'key_lines' => [22, 29],        // 源码中"关键代码"行号区间(渲染为高亮)
  'hints' => [
    '对比页面演示中:实例化 vs 反序列化,两者的对象属性来源差异',
    'flag_command 是 eval 的参数——把它改成读取 flag.php 的 PHP 代码',
    '本地构建 FLAG 类 → 修改属性 → serialize → urlencode 后提交',
  ],
  'wp' => 'writeups/level7.php',  // 初期可先指向 GitHub README 锚点
],
```

## 3. 接入方式(对现有文件的侵入度:每关 +2 行)

```php
<?php
require __DIR__ . '/../template/_header.php';   // ← 新增
/* ---------- 以下原有题目代码一字不动 ---------- */
class FLAG { /* ... */ }
unserialize($_POST['o']);
/* --------------------------------------------- */
require __DIR__ . '/../template/_footer.php';   // ← 新增
```

- `_header.php` 负责顶栏/标题/Tab 容器;原页面里的 `highlight_file(...)` 输出
  由 `_footer.php`(或输出缓冲)捕获后渲染进"源码"Tab——**展示的还是同一份源码**。
- 目录页 `index.php` 同步重排:章节分组 + 难度/模式徽章 + localStorage 已完成标记
  + 顶部"食用说明"卡(怎么答题、工具、WP 在哪)。

## 4. WriteUP 策略

- 短期:解析 Tab 的"完整 WP"按钮 → GitHub README 对应锚点(零迁移成本);
- 中期:README 中 WriteUP 拆分到 `writeups/LevelN`(每关一页,同模板渲染),
  README 只留目录;镜像内通过 `.dockerignore` 决定是否随容器分发(见 §6)。
- 防剧透门:勾选确认 → 展开;展开状态不持久化,每次进入重新确认。

## 5. 视觉规范

- 亮色为主 + 跟随系统暗色(代码区在暗色下保证对比度,解决现有问题);
- 主色:靛蓝 `#4f6ef7`;引导关徽章=绿色,挑战关徽章=橙红,一眼可辨;
- 代码字体:`ui-monospace, SFMono-Regular, Menlo, Consolas`;
- 正文最大宽度 960px,移动端单列自适应(现有 50% 固定宽问题一并解决)。

## 6. 附:既有代码"刻意 vs 无意"审计结论(对应本次复核)

**判定为刻意设计,必须原样保留:**

| 项 | 说明 |
|---|---|
| `php:5.4-apache` 基础镜像 | Level 11 的 CVE-2016-7124(PHP<5.6.25/7.0.10)复现依赖此版本,必修课,不可升级替代 |
| Level 11 全部逻辑(含页面底部 `phpinfo()`) | CVE 关卡;phpinfo 可让学员确认环境版本、判断 CVE 适用性,保留 |
| 全站 `eval()` 体系、`system('cat /flag')` | 教学核心,保留 |
| Level 9 无 flag.php(flag 在 `/flag`) | README 明示"动态容器"设计,保留 |
| Apache `+Indexes` 目录列表 | 便于学员浏览文件;保留行为本身 |
| `highlight_file` 裸输出风格 | 被 UI 层替换展示方式,但展示内容不变 |

**判定为无意 bug,建议修复(不损失任何考点):**

| 项 | 说明 | 修法 |
|---|---|---|
| `Level7/demo` 语法错误 | 单引号串内嵌单引号未转义,`php -l` 实测 parse error;本意是展示"实例化 vs 反序列化"对比,与引号写法无关 | 改为双引号转义或 heredoc |
| `highlight_file(source)`/`(demo)` 裸常量(L3/4/7/8) | PHP≤7 可运行(降级为字符串),PHP8 直接 Fatal;无教学意图 | 加引号,行为零变化 |
| `Level5` `array(a=>"Hello",b=>"CTF")` 裸键 | 同上,本关考点是序列化格式而非常量 | 加引号 |
| Level 8 flag 前缀 `FLAG{}` 与全站 `HelloCTF{}` 不一致 | 疑似笔误 | 统一(可选) |

> 修复均不影响 5.4 环境下的任何关卡可解性与 CVE 复现。
